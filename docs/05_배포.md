# 05. 배포 — Vercel + Supabase

> M0-4(#9). 처음 한 번만 하면 이후에는 `main` 머지 → 자동 배포, PR마다 미리보기 주소가 생긴다.
> 키 값은 채팅에 붙여 넣지 않는다. 모두 사용자가 각 서비스 화면에 직접 넣는다.

## 구성 한눈에

| 항목 | 값 |
|---|---|
| 호스팅 | Vercel Hobby(무료), 함수 지역 `icn1`(서울) — `vercel.json` |
| 운영 배포 | `main` 브랜치 푸시(PR 머지) 때 자동 |
| 미리보기 배포 | PR마다 자동. Vercel 봇이 PR에 주소를 댓글로 단다 |
| 상태 확인 | `<배포 주소>/api/health` → `{"ok":true,"db":"up"}` |
| DB 깨우기 | `.github/workflows/keepalive.yml`이 월·목에 `/api/health` 호출 (Supabase 무료 플랜 7일 일시정지 방지) |

## 1. Vercel 가입과 저장소 연결

1. https://vercel.com 접속 → **Sign Up**
2. 플랜 선택에서 **Hobby**(개인 용도) → 이름 입력 → **Continue with GitHub** → GitHub 로그인·권한 허용
3. 대시보드에서 **Add New… → Project**
4. **Import Git Repository** 목록에서 `chatbot_re` 옆 **Import**
   - 목록에 없으면 **Adjust GitHub App Permissions** → Repository access에서 `chatbot_re`를 선택하고 저장
5. **Configure Project** 화면
   - Framework Preset: **Next.js** (자동 인식). Root Directory `./`, Build·Install 명령은 기본값 그대로(pnpm 자동 인식)
   - **Environment Variables**를 펼치고 아래 2절대로 입력
6. **Deploy** → 1~3분 뒤 축하 화면이 나오면 완료. **Continue to Dashboard**

## 2. 환경 변수 (Vercel)

지금(M0) 필요한 것은 Supabase 4개뿐이다. 값은 내 컴퓨터의 `.env.local`에서 복사한다.

| 이름 | 비고 |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | |
| `SUPABASE_SERVICE_ROLE_KEY` | 비밀. 서버에서만 쓴다 |
| `DATABASE_URL` | Transaction pooler 주소(포트 6543) |

- Key 칸에 `.env.local` 내용을 통째로 붙여 넣으면 여러 개가 한 번에 채워진다. 이때 **값이 빈 줄(LLM 키 등)은 지운다.**
- 적용 환경(Environments)은 기본값인 Production·Preview·Development 모두 체크 그대로 둔다.
- 나중에 바꾸려면: 프로젝트 → **Settings → Environment Variables**. 바꾼 뒤에는 **Deployments → 최신 배포 ⋯ → Redeploy** 해야 반영된다.
- LLM 키(M0-5)는 그때 같은 화면에서 추가한다.

## 3. 배포 확인

1. 프로젝트 대시보드의 **Domains**에 있는 주소(예: `chatbot-re-tew1.vercel.app`)를 연다 → 홈 화면
2. 주소 뒤에 `/api/health`를 붙여 연다
   - `{"ok":true,"db":"up"}` → 정상
   - `{"ok":false,"db":"down"}` → `DATABASE_URL` 값이나 Supabase 일시정지 여부 확인. 로그는 **Logs** 탭
3. 이 운영 주소를 Claude에게 알려 준다(주소는 비밀이 아니다). README에 적는다.

## 4. Supabase 인증 주소 등록

로그인(M0-3) 후 돌아올 주소를 Supabase가 허용해야 한다.

1. Supabase 대시보드 → 프로젝트 → **Authentication → URL Configuration**
2. **Site URL**: 운영 주소로 바꾼다 (예: `https://chatbot-re-tew1.vercel.app`)
3. **Redirect URLs → Add URL**로 세 개를 넣는다
   - `http://localhost:3000/**` (로컬 개발)
   - `https://chatbot-re-tew1.vercel.app/**` (운영)
   - `https://*-<Vercel 계정 슬러그>.vercel.app/**` (PR 미리보기)
     - 슬러그는 미리보기 주소 끝부분이다. 예: 미리보기가 `chatbot-re-git-9-abc-iamp00rs-projects.vercel.app`이면 `https://*-iamp00rs-projects.vercel.app/**`
4. **Save**

Google OAuth 쪽(Google Cloud 콘솔)의 리디렉션 URI는 Supabase 주소라서 바꿀 필요 없다.

## 5. DB 깨우기 예약 작업 켜기

1. GitHub 저장소 → **Settings → Secrets and variables → Actions → Variables** 탭 → **New repository variable**
   - Name: `PRODUCTION_URL`, Value: 운영 주소 (예: `https://chatbot-re-tew1.vercel.app`) → **Add variable**
2. 시험 실행: 저장소 → **Actions → Keepalive → Run workflow** → 초록 체크면 완료
   - 변수가 없으면 작업은 실패하지 않고 경고만 남기고 건너뛴다.

> 깨우기는 "7일 무요청"만 막는다. 이미 일시정지됐다면 Supabase 대시보드에서 **Restore project**를 누른다. 데모 전날에는 직접 한 번 열어 본다(03 §7 위험).

## 6. 미리보기 배포 보기

- PR을 열면 Vercel 봇 댓글의 **Visit Preview** 링크로 연다.
- 미리보기는 기본으로 **Vercel 로그인한 사람만** 볼 수 있다(Deployment Protection). 사용자는 Vercel에 로그인돼 있으면 그대로 열린다.
- 미리보기도 운영과 같은 Supabase DB를 쓴다(무료 플랜 프로젝트 2개 제한). 미리보기에서 만든 데이터는 실제 데이터다.
