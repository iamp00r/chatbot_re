# M0-1 프로젝트 초기화 — 뼈대와 자동 검사

> 앱의 빈 뼈대를 세우고, 코드가 올라올 때마다 자동으로 검사하는 장치를 만들었다 · PR #11 · 2026-11-27

## 한 줄로

"Loom" 제목만 있는 빈 웹앱을 만들고, **AI가 쓴 코드든 사람이 쓴 코드든 검사 5종을 통과해야만 합칠 수 있게** 했다.

## 무엇을 만들었나

- 웹앱 뼈대: Next.js 16 + TypeScript (`src/app/`)
- 화면 꾸미기 도구: Tailwind CSS 4 + shadcn/ui 버튼 컴포넌트 (`src/components/ui/button.tsx`)
- 코드 정리·검사 도구: Prettier(서식), ESLint(실수 찾기), TypeScript(타입 검사)
- 테스트 도구: Vitest(작은 단위 테스트, `tests/unit/`), Playwright(실제 브라우저로 화면 테스트, `tests/e2e/`)
- 자동 검사(CI): GitHub Actions (`.github/workflows/ci.yml`)
- 설정 견본: `.env.example` (실제 키는 각자 컴퓨터의 `.env.local`에만)

## 어떻게 동작하나

```
PR을 올린다
  → GitHub가 빈 컴퓨터를 하나 빌려 코드를 받는다
  → ① 서식 검사 ② 실수 검사 ③ 타입 검사 ④ 단위 테스트 ⑤ 실제 빌드 후 브라우저 테스트
  → 하나라도 실패하면 빨간 X, 머지 버튼이 잠긴다 (main 보호 규칙)
  → 모두 통과하면 초록 체크 → 사용자가 검수하고 머지
```

로컬에서도 같은 명령(`pnpm format:check && pnpm lint && pnpm typecheck && pnpm test && pnpm e2e`)으로 똑같이 검사한다.

## 왜 이렇게 했나

| 결정 | 고른 것 | 다른 선택지 | 이유 |
|---|---|---|---|
| 웹 프레임워크 | Next.js (App Router) | 화면(React)과 서버를 따로 | 화면과 서버 API를 한 프로젝트에서 만든다. 2인 팀에 관리할 것이 적고, 배포처(Vercel)와 궁합이 좋다 |
| 언어 | TypeScript | JavaScript | 데이터 모양(타입)을 미리 정해 두면 잘못된 값을 실행 전에 잡는다. AI가 쓴 코드의 실수를 기계가 먼저 걸러 준다 |
| 화면 부품 | shadcn/ui | MUI 같은 완성형 라이브러리 | 부품 코드를 프로젝트 안에 복사해 직접 고칠 수 있다. 디자인을 자유롭게 바꾸기 쉽다 |
| 테스트 | Vitest + Playwright | Jest, Cypress | 빠르고 설정이 간단하다. Playwright는 실제 크롬으로 화면을 눌러 본다 |
| 자동 검사 | GitHub Actions + main 보호 | 사람이 매번 확인 | **사용자는 코드를 읽지 않고 동작만 검수한다.** 그래서 "기계가 먼저 막는 장치"가 필수다 |
| 패키지 관리자 | pnpm | npm | 설치가 빠르고 디스크를 덜 쓴다 |

## 사용자가 한 일

- GitHub 저장소 `main` 보호 설정: PR 필수, CI 통과 필수, Squash 머지만 허용, 머지된 브랜치 자동 삭제

## 확인한 방법

- PR에서 CI 초록 체크 확인
- 홈 화면에 "Loom" 제목이 보이는지 단위 테스트·브라우저 테스트로 확인

## 용어 풀이

| 용어 | 뜻 |
|---|---|
| 프레임워크 | 앱을 만드는 기본 틀. 집으로 치면 골조 |
| 빌드 | 사람이 쓴 코드를 실제로 실행할 수 있는 형태로 바꾸는 과정 |
| CI | Continuous Integration. 코드가 올라올 때마다 자동으로 검사하는 것 |
| 단위 테스트 / E2E 테스트 | 부품 하나를 따로 시험 / 사용자처럼 처음부터 끝까지 눌러 보며 시험 |
| 린트(lint) | 문법은 맞지만 실수일 가능성이 높은 코드를 찾아 주는 검사 |

## 설명할 때 (30초 버전)

> 코드 대부분을 AI가 쓰기 때문에, 첫 단계에서 "검사를 통과하지 못하면 합칠 수 없는 구조"부터 만들었습니다. PR마다 서식·타입·단위 테스트·실제 브라우저 테스트가 자동으로 돌고, 하나라도 실패하면 머지가 막힙니다. 저는 코드 한 줄 한 줄 대신 결과 동작을 검수하고, 기계가 품질의 바닥을 지킵니다.
