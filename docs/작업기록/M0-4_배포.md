## 개요

GitHub 저장소를 Vercel에 연결해 **main 머지 → 운영 자동 배포, PR → 미리보기 배포**가 되게 했다. 운영 주소 https://chatbot-re.vercel.app.
배포·DB 연결 상태를 확인하는 `/api/health`를 만들고, 이를 주 2회 호출해 **Supabase 무료 플랜의 7일 무요청 일시정지를 막는** 예약 작업을 붙였다.

## 구현 내용

### `/api/health` (`src/app/api/health/route.ts`)
```ts
export async function GET() {
  await connection();                       // 요청 시점에 실행되도록 (빌드 때 프리렌더 금지)
  try {
    await getDb().execute(sql`select 1`);   // DB 왕복 1회
    return Response.json({ ok: true, db: "up" }, { headers: { "Cache-Control": "no-store" } });
  } catch (error) {
    console.error("[health] DB 확인 실패", error);   // 원인은 서버 로그에만
    return Response.json({ ok: false, db: "down" }, { status: 503, headers: { "Cache-Control": "no-store" } });
  }
}
```
- 인증 없음(명세 §9의 예외). 응답에 오류 원문을 담지 않는다 — 연결 문자열·사용자명 같은 정보가 오류 메시지에 섞일 수 있어서.
- `Cache-Control: no-store`: CDN·브라우저가 응답을 캐시하면 DB가 죽어도 "up"이 보일 수 있다.

### `vercel.json`
```json
{ "regions": ["icn1"] }
```
서버리스 함수를 서울 리전에서 실행. Supabase도 서울(ap-northeast-2)이라 함수↔DB 왕복이 같은 지역 안에서 끝난다.

### keepalive (`.github/workflows/keepalive.yml`)
```yaml
on:
  schedule: [{ cron: "17 3 * * 1,4" }]   # UTC 월·목 03:17 = KST 12:17
  workflow_dispatch:                     # 수동 실행 버튼
env: { PRODUCTION_URL: ${{ vars.PRODUCTION_URL }} }
run: curl --fail --max-time 30 --retry 3 --retry-delay 20 --retry-all-errors "$PRODUCTION_URL/api/health"
```
- 저장소 **변수**(`vars`, 비밀 아님)에서 주소를 읽는다. 없으면 경고만 남기고 성공 처리 → 설정 전에도 Actions가 빨갛게 되지 않는다.
- `--fail`: 503이면 curl이 실패 코드로 끝나 작업이 빨간색이 된다 → DB 이상을 Actions 알림으로 알 수 있다.
- 일시정지 직후 첫 요청이 느릴 수 있어 재시도.
- 분을 `:17`로 둔 이유: GitHub 예약 작업은 정각에 몰려 지연되기 쉽다.

## 동작 방식

```
PR 푸시 ──→ Vercel: 해당 브랜치 빌드 → chatbot-re-git-<브랜치>-travel-yaho.vercel.app (Preview)
              └ Vercel 봇이 PR에 미리보기 링크 댓글
main 머지 ─→ Vercel: main 빌드 → chatbot-re.vercel.app (Production) 교체

월·목 12:17 ─ GitHub Actions ─→ /api/health ─→ (icn1 함수) ─→ Supabase pooler ─→ select 1
```

환경 변수는 Vercel 프로젝트 설정에 넣고(Production·Preview·Development 공통), 빌드·실행 시 `process.env`로 주입된다. 바꾼 뒤에는 재배포해야 반영된다.

| 주소 보관 | Actions **variable** | secret | 운영 주소는 공개 정보. 로그에 그대로 보여야 디버깅이 쉽다 |
| 미리보기 DB | 운영과 같은 Supabase | 미리보기 전용 프로젝트 | 무료 플랜 프로젝트 2개 제한. 개인 실험이라 감수(미리보기 데이터도 실데이터) |

## 문제와 해결

| 문제 | 원인 | 해결 |
|---|---|---|
| (예방) `/api/health`가 빌드 때 한 번만 실행되고 결과가 고정될 위험 | Next 16 Cache Components에서 GET 핸들러는 런타임 데이터를 쓰지 않으면 프리렌더된다. 드라이버 쿼리는 Next가 "런타임 데이터"로 인식하지 못함 | `await connection()`으로 동적 렌더링 강제. E2E에서 DB 없는 환경의 503 응답을 확인해 매 요청 실행됨을 검증 |
| PR에 Vercel 배포가 2줄 | 저장소를 두 번 Import해서 프로젝트 2개(`chatbot-re`, 이름 충돌로 `chatbot-re-tew1`)가 같은 저장소에 연결됨 | 하나 삭제. 남은 프로젝트에 도메인 `chatbot-re.vercel.app` 추가 |
| 원하는 주소 | `*.vercel.app` 서브도메인은 전역에서 유일 | 비어 있어 등록 가능했음 |
| 이 클라우드 작업 환경에서 배포 주소 접속 불가 | 작업 환경의 아웃바운드 네트워크 정책 | 확인은 사용자가 브라우저로, keepalive 실행 로그로 교차 검증 |

## 개념 정리

- **서버리스 함수**: 요청이 올 때 함수 인스턴스가 떠서 처리하고, 한동안 요청이 없으면 내려간다. 다시 뜰 때 지연이 생긴다(콜드 스타트). 항상 켜진 서버가 없어서 무료 운영이 가능하다. 실행 시간 제한이 있어 긴 작업(기억 추출)은 쪼개야 한다(명세 §2).
- **Preview / Production 배포**: Vercel은 브랜치마다 독립된 배포를 만든다. 운영 도메인은 production 브랜치(main)의 최신 배포에만 연결된다. 미리보기는 기본적으로 Vercel 로그인 사용자만 볼 수 있다(Deployment Protection).
- **`NEXT_PUBLIC_` 접두사**: 이 접두사가 붙은 환경 변수만 빌드 때 브라우저 번들에 들어간다. `SUPABASE_SERVICE_ROLE_KEY`처럼 접두사가 없는 값은 서버에서만 읽힌다.
- **동적 렌더링 강제 (`connection()`)**: "이 코드는 실제 요청이 들어왔을 때만 실행하라"는 신호. 이후 코드는 빌드 때 실행되지 않는다. Next 16 이전의 `export const dynamic = 'force-dynamic'`에 해당하는 역할.
- **OAuth Redirect URL 허용 목록**: 로그인 후 인증 코드를 돌려줄 주소를 미리 등록된 것으로 제한해, 공격자 주소로 토큰이 가로채이는 것(open redirect)을 막는다. `*`는 한 단계 이름, `**`는 하위 경로 전체를 뜻한다.
- **cron 표현식**: `분 시 일 월 요일`. GitHub Actions는 UTC 기준이고, 부하가 몰리면 실행이 늦거나 건너뛸 수 있다.
- **HTTP 503**: Service Unavailable. "서버는 살아 있지만 지금 제 기능을 못 한다"는 뜻이라 DB 장애 표현에 적합하다.
