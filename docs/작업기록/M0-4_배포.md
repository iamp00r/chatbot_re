# M0-4 인터넷에 올리기 (Vercel 배포)

> 앱을 인터넷 주소로 열 수 있게 하고, PR마다 미리보기 주소가 생기게 했다 · PR #15 · 2026-11-28

## 한 줄로

**https://chatbot-re.vercel.app** 에서 앱이 열린다. 코드를 합치면 자동으로 새 버전이 올라가고, PR마다 따로 미리보기 주소가 생겨서 **검수를 링크 하나로** 할 수 있게 됐다.

## 무엇을 만들었나

- 상태 확인 주소 `/api/health` (`src/app/api/health/route.ts`): 앱이 살아 있고 DB에 닿으면 `{"ok":true,"db":"up"}`
- 서버 지역 설정 (`vercel.json`): 서울(`icn1`)
- DB 깨우기 예약 작업 (`.github/workflows/keepalive.yml`): 월·목 12:17(한국)에 `/api/health` 호출
- 설정 안내서 (`docs/05_배포.md`)
- 테스트: 상태 확인 주소의 정상·오류 응답 (`tests/unit/health.test.ts`, `tests/e2e/health.spec.ts`)

## 어떻게 동작하나

```
PR을 올린다 ─→ Vercel이 그 브랜치를 빌드 ─→ 미리보기 주소 (PR 댓글로 알려 줌)
PR을 머지한다 ─→ Vercel이 main을 빌드 ─→ 운영 주소(chatbot-re.vercel.app) 교체
```

```
월·목 12:17  GitHub Actions ─→ chatbot-re.vercel.app/api/health ─→ DB에 "select 1"
            (Supabase는 "최근 요청 있음"으로 보고 일시정지하지 않는다)
```

## 왜 이렇게 했나

| 결정 | 고른 것 | 다른 선택지 | 이유 |
|---|---|---|---|
| 호스팅 | Vercel Hobby(무료) | AWS, 자체 서버 | Next.js를 만든 회사라 설정이 거의 없다. GitHub와 연결만 하면 자동 배포·미리보기가 된다 |
| 서버 지역 | 서울 `icn1` | 미국(기본값) | DB가 서울에 있다. 서버가 미국이면 DB를 부를 때마다 태평양을 왕복한다 |
| 상태 확인 주소 | 만듦 | 없이 홈 화면만 확인 | 홈 화면은 DB 없이도 뜬다. "DB까지 연결됐는지"를 한 번에 보려면 따로 필요하다 |
| 오류 응답 | "down"만 알려 주고 원인은 서버 로그에만 | 오류 내용을 그대로 응답 | 오류 문장에 DB 주소·계정 같은 정보가 섞일 수 있다. 누구나 여는 주소라 숨긴다 |
| DB 깨우기 | GitHub Actions 예약 작업 | 유료 플랜, 외부 모니터링 서비스 | 무료 플랜은 7일 동안 요청이 없으면 DB가 멈춘다. 저장소 안에서 무료로 해결되고, 상태 확인 주소를 재사용한다 |
| 미리보기도 같은 DB 사용 | 같은 Supabase | 미리보기용 DB 따로 | 무료 플랜은 프로젝트 2개 제한. 개인 실험이라 감수한다 (미리보기에서 만든 데이터도 실제 데이터) |

## 사용자가 한 일

- Vercel 가입(GitHub 로그인), 저장소 가져오기, 환경 변수 4개 입력
- 실수로 생긴 프로젝트 2개 중 하나 삭제, 주소를 `chatbot-re.vercel.app`으로 지정
- Supabase 인증 주소 설정: Site URL, Redirect URLs 3개 (로그인 후 돌아올 주소 허용 목록)
- GitHub 저장소 변수 `PRODUCTION_URL` 등록

## 확인한 방법

- 미리보기·운영 주소에서 `/api/health` → `{"ok":true,"db":"up"}` (사용자 확인)
- Keepalive 수동 실행 → 성공, 로그에 `{"ok":true,"db":"up"}`
- CI: DB가 없는 환경에서는 `503 {"ok":false,"db":"down"}`이 나오는지 브라우저 테스트로 확인

## 겪은 일

- **Vercel 프로젝트가 2개 생김**: 가져오기를 두 번 해서 같은 저장소에 프로젝트가 둘 붙었다. PR마다 빌드가 두 번 돌았다. 하나를 지우고, 원하는 주소(`chatbot-re.vercel.app`)를 남은 프로젝트에 붙였다.
- **`vercel.app` 주소는 전 세계에서 하나씩**이라, 원하는 이름이 비어 있어야 쓸 수 있다.

## 용어 풀이

| 용어 | 뜻 |
|---|---|
| 배포 | 만든 앱을 인터넷에서 열 수 있게 서버에 올리는 것 |
| 미리보기 배포 | 합치기 전의 PR 버전을 임시 주소에 올린 것. 운영에는 영향 없음 |
| 환경 변수 | 코드 밖에 두는 설정값(키, 주소). 코드에 넣으면 GitHub에 공개되므로 따로 넣는다 |
| 서버리스 함수 | 요청이 올 때만 잠깐 켜지는 서버. 항상 켜 둘 필요가 없어 무료로 운영된다 |
| Redirect URL | 로그인 후 돌아와도 되는 주소 목록. 목록에 없는 주소로는 돌려보내지 않아 가로채기를 막는다 |
| 예약 작업(cron) | 정해진 시간마다 자동으로 실행되는 작업 |

## 설명할 때 (30초 버전)

> GitHub와 Vercel을 연결해서, 코드를 합치면 자동으로 배포되고 PR마다 미리보기 주소가 생기게 했습니다. 그래서 저는 코드를 보지 않고 링크를 열어 동작으로 검수합니다. 서버는 DB와 같은 서울 지역에 두어 왕복 시간을 줄였고, 무료 DB가 7일 무요청이면 멈추는 문제는 상태 확인 주소를 주 2회 부르는 예약 작업으로 무료로 해결했습니다.
