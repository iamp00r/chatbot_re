# 작업 기록 (개발 일지)

백로그 항목(M0-1, M1-5 …)마다 한 파일씩 남기는 개발 일지.
대화 기록을 뒤지지 않아도 **무엇을 구현했고, 어떻게 동작하며, 왜 그렇게 설계했는지, 무엇이 문제였는지**를 여기서 다시 공부할 수 있게 한다.

- 언제: 백로그 항목을 끝내는 PR 안에 함께 넣는다.
- 설계 원본은 `docs/02_기술명세서.md`. 여기는 실제 구현 기준의 기록이다(명세와 달라진 점 포함).
- 검수 중 나온 질문과 답도 해당 기록에 추가한다.

## 양식

```markdown
# M?-? 제목

| PR | 이슈 | 완료일 | 주요 파일 |
|---|---|---|---|

## 개요
(무엇을 위한 작업이고 결과로 무엇이 가능해졌나)

## 구현 내용
(파일별로 무엇을 했는지. 핵심 코드는 발췌해서 설명)

## 동작 방식
(요청·데이터 흐름. 필요하면 다이어그램)

## 설계 결정
| 결정 | 선택 | 대안 | 이유 |

## 문제와 해결
(겪은 오류·함정, 원인, 해결)

## 테스트·검증

## 명세서와 달라진 점

## 개념 정리
(이 작업에 쓰인 기술 개념을 공부용으로 정리)

## 참고
(관련 명세 절, 공식 문서 경로)
```
