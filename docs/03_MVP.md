> 기능 ID는 `01_기획서.md`, 설계 근거는 `02_기술명세서.md`(§번호)를 따른다.

## 1. MVP가 검증할 가설

| # | 가설 | 검증 방법 | 통과 기준 |
|---|---|---|---|
| H1 | 구조화 기억(그래프+표)은 줄거리 요약만 쓸 때보다 장기 대화의 회상 정확도를 높인다 | 평가 하네스 조건 B와 C 비교 (명세서 §11) | C가 B보다 +20%p |
| H2 | known_by 필터가 있으면 다인캐 대화에서 비밀 유출이 크게 준다 | 조건 C와 D 비교 | 유출률 C < 5%, D 대비 절반 이하 |
| H3 | 기억을 보고 고치는 기능이 실제 대화 경험을 낫게 한다 | 본인 사용 일지 (2주, 200턴 이상) + 수정 횟수 로그 | 정성 평가: "고친 뒤 다시 틀리지 않는다" |
| H4 | 이 모든 것을 저가 모델로 쓸 만한 속도와 비용에 돌릴 수 있다 | generation_logs | TTFT p50 < 2초, 턴당 비용 기록 |

## 5. 완료 정의 (Definition of Done)

- 인수 조건을 만족하고, 사용자(검수자)가 데모 시나리오로 확인했다.
- 핵심 로직(화자 선택, 검색 점수, 연산 적용, 무효화)에 단위 테스트가 있다.
- 주요 흐름 E2E 1개(로그인 → 작품 → 채팅 → 기억 수정)가 통과한다.
- 새 LLM 호출 경로는 generation_logs에 기록된다.
- 문서(명세서)와 구현이 다르면 문서를 고친다.

## 6. 데모 시나리오 (M4 포트폴리오용)

**시나리오 A: "기억이 보이는 장기 스토리" (1:1)**
1. 작품 "비 오는 학원가의 리아" 시작.
2. 30턴 동안 약속(시계탑), 리아의 취향(딸기우유), 사건(지도 조각)을 만든다.
3. 기억 탭 → 자동 추출된 표와 그래프를 보여 준다.
4. "딸기우유"를 "바나나우유"로 고친다 → 잠김.
5. 리아에게 "내가 좋아하는 우유 기억나?"가 아니라 "편의점 가자"라고만 말해도 리아가 바나나우유를 집는다.
6. "이번 응답에 쓰인 기억"으로 근거를 보여 준다.

**시나리오 B: "누가 무엇을 아는가" (3인)**
1. 작품 "왕립 아카데미 미스터리" (리아, 도윤, 사서 에반).
2. 도윤에게 귓속말: "사실 네가 왕족인 거 알아."
3. 리아에게 "도윤 좀 수상하지 않아?" → 리아는 왕족 이야기를 하지 않는다.
4. 기억 표에서 그 비밀의 아는 사람에 리아를 추가 → 리아의 반응이 바뀐다.
5. 평가 리포트의 유출률 표(known_by 켬/끔)를 보여 준다.

## 7. 리스크와 대응 (MVP 기간)

| 리스크 | 신호 | 대응 |
|---|---|---|
| 추출이 엉망 | M2-13 정밀도 < 70% | 메시지 범위 축소(6 → 4), 기존 기억 후보 수 조정, 소수 예시(few-shot) 추가, 추출 모델 한 단계 상향 |

| 일정 지연 | 마일스톤 50% 시점에 절반 미달 | 그래프 뷰(M2-9)와 이어 말하기(M3-3)를 v1로 미룸. 표와 known_by는 유지 |
