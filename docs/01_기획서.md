## 0. 한 줄 정의

**"기억이 보이고, 고칠 수 있는" AI 캐릭터 채팅.** 대화에서 생긴 인물·관계·사건을 **기억 그래프와 표**로 쌓아 사용자에게 보여 주고, 사용자가 직접 고칠 수 있게 한다. 여러 캐릭터가 한 방에서 대화할 때는 **"누가 무엇을 아는가"**를 구분해, 각 캐릭터가 자기가 아는 것만 말하게 한다.

가칭 *Loom*(베틀)은 대화라는 실로 기억을 엮는다는 뜻이다. 이름은 나중에 바꿀 수 있다.

## 1. 프로젝트 성격과 전제

| 항목 | 내용 |
|---|---|
| 목적 | 개인 실험 + 포트폴리오. 대외 출시·수익화는 하지 않는다 |
| 팀 | 2인 (사용자: 기획 결정·검수·테스트 / Claude: 문서·설계·구현) |
| 플랫폼 | 반응형 웹 우선. 모바일 앱은 이후 확장 |
| 콘텐츠 등급 | 전연령 |
| 비용 | 실험 규모라 엄격한 제약은 아니지만, 기본값은 저가 모델 + 무료 인프라 티어 |

**포트폴리오로서 보여 줄 것:** ① 동작하는 서비스(데모 URL), ② 기억 시스템 설계와 그 근거, ③ **기억 시스템의 효과를 수치로 보여 주는 평가 결과**(기억 기능 켬/끔 비교. §8 참고).

## 2. 배경과 시장

- 국내 AI 캐릭터 채팅은 제타(스캐터랩)와 크랙(뤼튼)이 이끈다. 크랙은 2026 지스타 메인 스폰서를 맡을 만큼 커졌다.
- 수익 모델은 서비스마다 다르다. 제타는 기본 대화는 무료이고 광고 제거·유료 모델에 재화를 쓴다. 크랙은 모델별로 정해진 재화를 대화마다 쓴다.
- 업계에서는 경쟁의 축이 모델 성능에서 **몰입 유지**로 옮겨 가고 있다고 본다.
- 청소년 보호가 사회적 쟁점이다. 연령 확인이 허술하고 선정적 대화가 쉽게 생성된다는 보도가 있었고, 국회입법조사처도 이런 서비스를 '관계형 AI'로 분류해 위험을 지적했다.
- 2026년 1월 22일 「AI 기본법」이 시행되어, AI 사업자에게 생성형 AI 결과물 표시 등 투명성 의무가 생겼다.

### 2.1 기억 기능 경쟁 현황 (2026-11 조사)

| 서비스 | 기억 방식 | 사용자 편집 | 한계 |
|---|---|---|---|
| 크랙 | 유저노트(수동 메모, 그룹·켜고 끄기, 공용/작품별), 장기기억 | 노트는 편집 가능 | 노트가 제작자 설정과 충돌하면 반영이 잘 안 됨. 구조 없는 자유 텍스트 |
| Character.AI | Story Memory(직접 작성) + Facts(자동 추출, 편집·끄기 가능, c.ai+ 전용) + Memory Usage | 가능 | 사실 목록 중심. 관계 구조나 "누가 아는가"는 없음 |
| 기타 국내 서비스 | 메모리북(N턴마다 자동 요약, 직접 수정), 기억 카드(인물·장소·아이템 자동 추출) | 가능 | 요약문·카드 단위. 관계 그래프 없음 |
| SillyTavern(오픈소스) | 로어북 + 그룹챗(발화 순서 전략) | 가능 | 고급 사용자용. 기억이 캐릭터별로 나뉘지 않음 |

**결론:** "자동 추출 + 사용자 편집"은 이미 여러 서비스에 있어서 그것만으로는 차별점이 되지 않는다. Loom의 차별점은 아래 세 가지다.

1. **관계 그래프**: 사실 목록이 아니라 인물 사이의 관계(엣지)와 그 변화를 저장한다.
2. **아는 사람(known_by) 범위**: 기억마다 아는 사람이 정해져 있어, 다중 캐릭터 대화에서 정보 비대칭(비밀, 오해, 반전)이 생긴다.
3. **시간 이력**: 바뀐 사실은 지우지 않고 "무효화"해서 이력으로 남긴다. "3화에서는 적이었지만 지금은 동료" 같은 흐름을 추적한다(Zep/Graphiti의 시간 인식 지식 그래프에서 착안).

## 3. 문제 정의

| # | 사용자 문제 | 현재의 대처 | Loom의 해결 |
|---|---|---|---|
| P1 | 대화가 길어지면 캐릭터가 설정과 사건을 잊는다 | 유저노트를 손으로 적거나 재요약 | 자동 추출된 구조화 기억 + 관련 기억만 골라 주입 |
| P2 | AI가 무엇을 기억하는지 알 수 없다 | 직접 물어보기 | 그래프·표로 시각화 |
| P3 | 잘못 기억해도 바로잡기 어렵다 | 메시지 수정, 되감기 | 표에서 직접 수정 + 잠금 |
| P4 | 다인캐 대화에서 캐릭터가 모르는 사실을 말하고, 말투가 섞인다 | 프롬프트 요령 | 화자별 프롬프트 + known_by 필터 |
| P5 | 다인캐에서 캐릭터끼리 대화가 이어지지 않는다 | 수동 호출 | 화자 선택 규칙 + 자동 이어 말하기(최대 N회) |

## 4. 타깃 사용자

- **주 사용자(실험 단계):** 제작자 본인. 직접 써 보며 기억 품질을 평가한다.
- **가상 페르소나 A, "스토리 몰입러" (20대):** 같은 캐릭터와 수백 턴씩 장기 스토리를 진행한다. 캐릭터가 설정을 잊는 것에 가장 크게 불만을 느낀다.
- **가상 페르소나 B, "세계관 빌더" (10대 후반~20대):** 여러 캐릭터가 나오는 작품을 만들고, 인물 관계도를 직접 설계하고 싶어 한다.

## 5. 핵심 개념

| 용어 | 정의 |
|---|---|
| **캐릭터(Character)** | 이름, 외형, 성격, 말투, 예시 대화를 가진 AI 인물 |
| **작품(Story)** | 세계관 + 등장 캐릭터 1명 이상 + 인트로. 1:1 채팅도 등장인물이 한 명인 작품으로 다룬다 |
| **페르소나(Persona)** | 사용자가 연기하는 인물 설정 |
| **채팅방(Room)** | 작품 하나를 플레이하는 한 회차. 기억은 채팅방 단위로 쌓인다 |
| **노드(Node)** | 기억 그래프의 개체: 인물 / 장소 / 물건 / 사건 / 집단 / 개념 |
| **관계(Edge)** | 두 노드 사이의 관계. 예: `리아 → 사용자 : 소꿉친구, 호감 +60` |
| **기억(Memory)** | 한 줄짜리 사실·사건·약속·비밀. 관련 노드, 중요도, **아는 사람**, 출처 메시지를 가진다 |
| **원작 기억(Canon)** | 제작자가 작품에 넣어 둔 초기 노드·관계. 채팅방을 시작할 때 복사된다 |
| **잠금(Lock)** | 사용자가 확정한 항목. AI가 자동으로 고칠 수 없다 |

### 6.2 캐릭터·작품 제작
제타·크랙 제작자들이 겪는 문제를 반영해 입력칸을 나눈다. 핵심 설정이 예시 대화에만 있으면 잘 지켜지지 않고, 인트로 장면이 예시에 들어가면 같은 장면이 반복된다는 경험담이 많다.

| ID | 기능 | 우선 |
|---|---|---|
| F-CR-1 | 캐릭터 기본: 이름, 한 줄 소개, 아바타(업로드) | P0 |
| F-CR-2 | 캐릭터 상세: 외형 / 성격 / 말투 / 배경 / 반드시 지킬 것 (구역별 입력) | P0 |

```

/rooms/[id]             채팅 화면 ─┬─ 오른쪽 패널(데스크톱)/하단 시트(모바일)
                                    ├─ 기억 탭: [표] [그래프] [줄거리] [변경 기록]
                                    ├─ 장면 탭: 참여자 토글, 화자 지정, 이어 말하기
                                    └─ 설정 탭: 페르소나, 모델, 응답 길이
/personas               페르소나 관리
/admin/usage            사용량 (본인)
/admin/prompts/[msgId]  프롬프트 검사기
```

### 7.1 채팅 화면 와이어프레임 (데스크톱)

```
┌───────────────────────────────────────────┬──────────────────────────┐
│ ← 작품명 · 채팅방명            [장면 2/3명] │ 기억 │ 장면 │ 설정        │
├───────────────────────────────────────────┼──────────────────────────┤
│ (리아) *창밖을 보며* 비가 오네.             │ [표] [그래프] [줄거리]    │
│                                   ◀ 2/3 ▶ │ ┌──────────────────────┐ │
│ (나)   우산 같이 쓸래?                      │ │ 내용        │아는 사람│🔒│ │
│ (도윤) *문을 열고 들어온다* ...             │ │ 리아는 비를…│리아,나  │  │ │
│                                           │ │ 도윤은 사실…│도윤     │🔒│ │
│ 💡 새 기억 2개 · 관계 1개 변경 [보기][되돌리기]│ └──────────────────────┘ │
├───────────────────────────────────────────┤ + 기억 추가               │
│ [화자: 자동▾] [메시지 입력…]  [귓속말] [전송]│                          │
└───────────────────────────────────────────┴──────────────────────────┘
```

### 7.2 핵심 사용자 흐름

1. **작품 만들기 → 대화:** 캐릭터 작성 → 작품 생성 → (선택) 관계도 → 인트로 → 대화 시작 → 인트로 메시지와 원작 기억이 채팅방에 복사됨.
2. **기억 확인·수정:** 대화 중 "새 기억" 알림 → 기억 탭 → 잘못된 항목 수정 → 자동 잠금 → 다음 응답부터 반영.
3. **비밀이 있는 다인캐:** 도윤에게 귓속말 → 기억 "사용자가 도윤에게만 X를 털어놓음"(아는 사람: 도윤, 나) → 리아는 X를 모르는 채로 대화.
4. **되감기:** 메시지 12로 되감기 → 13번 이후에서 나온 자동 기억은 무효화(잠긴 항목은 유지하고 사용자에게 알림).

## 8. 성공 지표 (실험 지표)

출시하지 않으므로 사업 지표보다 **품질 지표**를 본다.

| 지표 | 측정 방법 | 목표(가설) |
|---|---|---|
| **기억 회상 정확도** | 미리 짠 50~100턴 시나리오를 재생한 뒤 질문 세트(예: "3일 전 약속 장소는?")로 채점. 기억 기능 끔 / 요약만 / 그래프+표 세 조건을 비교 | 그래프+표가 요약만보다 +20%p |
| **정보 유출률(다인캐)** | 비밀 시나리오에서, 모르는 캐릭터가 비밀을 언급한 비율 | 5% 미만 |
| **추출 정밀도** | 자동 추출 기억 중 사람이 "맞다"고 판정한 비율 | 85% 이상 |
| **사용자 수정 빈도** | 100턴당 사용자가 기억을 고친 횟수 (낮을수록 추출 품질이 좋음) | 추세 관찰 |
| **첫 토큰 지연(TTFT)** | p50 / p95 | p50 2초 미만 |
| **턴당 비용** | 토큰 로그 | 기록·관찰 |

평가 결과는 그대로 포트폴리오의 핵심 근거가 된다.

## 9. 콘텐츠 정책 (전연령)

- **금지:** 성적 묘사·암시, 미성년자를 연애·성적 대상으로 삼는 설정, 노골적 폭력·고어, 자해·자살 조장, 혐오 표현, 실존 인물 사칭, 범죄 방법 안내.
- **허용:** 일상, 모험, 미스터리, 감정 서사, 가벼운 로맨스(전연령 수위), 갈등과 악역(묘사 수위 제한).
- **기존 작품 캐릭터:** 외형과 성격을 그대로 베끼는 2차 창작은 비공개만 허용한다. 공개하려면 독창적이어야 한다.
- **위기 대응:** 사용자의 자해·위기 신호가 감지되면 캐릭터 연기를 잠시 멈추고 도움을 받을 수 있는 곳을 안내한다.
- **표시:** 채팅 화면에 AI 생성 콘텐츠임을 상시 표시한다.

## 10. 범위 밖 (Non-goals)

결제·재화·광고, 이미지 생성, 음성, 랭킹·추천 알고리즘, 댓글·팔로우, 네이티브 앱, 성인 콘텐츠.

## 11. 로드맵

| 단계 | 내용 |
|---|---|
| **MVP ①** | 1:1 채팅 코어 (작품, 캐릭터, 스트리밍, 재생성, 수정, 되감기, 프롬프트 검사기) |
| **MVP ②** | 기억 시스템 (자동 추출, 표 편집, 잠금, 줄거리, 그래프 뷰) + 평가 하네스 |
| **MVP ③** | 다중 캐릭터 (화자 선택, 이어 말하기, known_by, 장면 참여자, 귓속말) + 모더레이션 |
| v1 | 원작 관계도 편집, 변경 기록·되돌리기, 신고, 사용량 대시보드, 임베딩 검색 |
| v2 | 감독 모드, 기억 타임라인, 기억 가져오기, PWA/앱 |

## 12. 리스크

| 리스크 | 영향 | 대응 |
|---|---|---|
| 자동 추출 품질이 낮아 쓰레기 기억이 쌓임 | 핵심 가치 훼손 | 중요도 기준, 중복 병합, 검증 스키마, 평가 세트로 프롬프트 개선 |
| 기억 주입이 오히려 응답 품질을 떨어뜨림(과잉 정보) | 몰입 저하 | 토큰 예산 상한, 관련도 점수, "쓰인 기억 보기"로 디버깅 |
| 다인캐 비용과 지연이 커짐 | 사용감 저하 | 이어 말하기 상한, 화자 선택은 규칙 기반(LLM 호출 없음) |
| 저가 모델의 한국어 롤플레이 품질 | 몰입 저하 | 모델 추상화로 교체 쉽게, 초기에 2~3종 블라인드 비교 |
| 무료 인프라 제약(DB 일시정지 등) | 데모 중단 | 데모 전 깨우기, 필요하면 유료 전환 |
| 모더레이션 오탐·미탐 | 안전·사용감 | 임계값 조정, 걸린 사례 로그 검토 |

## 13. 열린 질문

1. 서비스 정식 이름
2. 기본 채팅 모델 (MVP ① 초기에 2~3종 블라인드 비교로 정하기)
3. 그래프 뷰를 모바일에서도 제공할지 (기본은 표만, 그래프는 데스크톱만)
4. 공개 작품을 둘지, 완전히 개인용으로 둘지 (포트폴리오 데모용으로는 "링크 공유"만 있어도 충분)
