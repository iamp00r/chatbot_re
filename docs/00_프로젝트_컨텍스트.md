# 00. 프로젝트 컨텍스트 — 가칭 Loom (AI 캐릭터 채팅)

> 새 세션을 시작할 때 이 문서부터 읽는다. 결정이 바뀌면 이 문서를 먼저 고친다.
> 최종 갱신: 2026-11-28 (M0-4 완료)

## 한 줄 요약
"기억이 보이고, 고칠 수 있는" AI 캐릭터 채팅(크랙·제타류). 대화에서 생긴 인물·관계·사건을 **기억 그래프 + 표**로 쌓아 사용자가 보고 고치며, 다중 캐릭터 대화에서는 **아는 사람(known_by)** 범위로 각 캐릭터가 자기가 아는 것만 말하게 한다.

## 확정된 전제
| 항목 | 결정 |
|---|---|
| 목적 | 개인 실험 + 포트폴리오. 대외 출시·홍보·수익화 없음 |
| 팀 | 2인: 사용자(기획 결정·검수·테스트), Claude(문서·설계·구현) |
| 플랫폼 | 반응형 웹 우선, 앱은 나중 |
| 등급 | 전연령 |
| 비용 | 엄격한 제약 아님. 기본값은 저가 모델 + 무료 인프라 |
| 작업 방식 | 사용자는 매번 묻지 않아도 진행하길 원함. 중요 단계(기획·명세·MVP)는 꼼꼼히 검토하고 웹 자료를 참고 |

## 핵심 설계 결정 (상세는 02 §16 ADR)
- 스택: Next.js(App Router, TS) + Vercel AI SDK + Supabase(Postgres, Auth, RLS) + Drizzle + TanStack Table + React Flow
- 1:1 채팅도 "등장인물 1명인 작품"으로 통일
- 기억 3층: 최근 대화 / 줄거리 요약 / 구조화 기억(노드·관계·기억)
- 추출은 응답 후 비동기, LLM 1회 호출 + 코드 검증. 삭제하지 않고 무효화·대체
- 사용자가 고친 항목은 자동 잠금 → AI는 "제안"만 가능
- 검색은 규칙 점수(중요도·언급·최근성·trigram), MVP에서 임베딩 없음
- 다인캐: 요청 하나에 화자 하나, 화자 관점으로 기록·기억을 거름, 귓속말·장면 참여자
- 평가 하네스로 기억 효과를 수치화 (포트폴리오 핵심)

### 다음 할 일 (순서대로)
1. **M0-3 로그인 (#8)** — 새 대화에서 시작한다. 이슈 #8의 할 일 목록을 따른다.
   - `@supabase/ssr`로 서버·브라우저 클라이언트, 세션 갱신. Next.js 16에서는 **`middleware.ts`가 폐기되고 `proxy.ts`(`src/proxy.ts`)로 바뀌었다** — `node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/proxy.md` 참고. Supabase 예제의 middleware 코드를 그대로 옮기지 않는다.
   - `/login`(Google 버튼 + 이메일 매직링크), `/auth/callback`, 첫 로그인 시 닉네임 입력 → `profiles` 생성(RLS는 M0-2에 있음, docs/02 §4.2).
   - 로그인 안 된 사용자는 `/login`으로 보낸다. 단 **`/api/health`는 인증 없이 열어 둔다**(keepalive가 호출).
   - 사용자 쪽 준비는 끝났다: Google OAuth 제공자 켬, Supabase Site URL·Redirect URLs 등록(아래 메모). 새로 할 설정 없음.
   - 인증 PR이므로 올리기 전에 `security-review`를 돌린다. 검수는 PR 미리보기 주소에서 사용자가 실제 로그인으로 확인한다.
   - 이 PR에서 Supabase 클라이언트용 환경 변수 외에 새 변수가 생기면 `.env.example`과 Vercel 둘 다에 넣도록 안내한다.

### 작업 환경 메모
- 배포: 운영 https://chatbot-re.vercel.app (Vercel 프로젝트 `chatbot-re`, 계정 슬러그 `travel-yaho`). `main` 머지 → 자동 배포, PR마다 미리보기(`chatbot-re-git-<브랜치>-travel-yaho.vercel.app`, Vercel 로그인한 사람만 열림). 미리보기도 운영과 같은 Supabase DB를 쓴다.
- Vercel 환경 변수: Supabase 4개(`NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, `DATABASE_URL`). 새 변수는 `.env.local`과 Vercel 양쪽에 넣어야 하며, Vercel에서 바꾼 뒤에는 Redeploy가 필요하다.
- Supabase Auth URL: Site URL `https://chatbot-re.vercel.app`, Redirect URLs `http://localhost:3000/**`, `https://chatbot-re.vercel.app/**`, `https://chatbot-re-*-travel-yaho.vercel.app/**`.
- DB 깨우기: `.github/workflows/keepalive.yml`이 저장소 변수 `PRODUCTION_URL`로 `/api/health`를 호출. 실패하면 Actions에서 확인.
- 사용자 준비 완료: Supabase 프로젝트(서울, 마이그레이션·RLS 적용), `.env.local`(Supabase 키 3개 + `DATABASE_URL`), Google OAuth(Supabase Google 제공자 켬), main 보호(Squash만 허용, PR·CI 통과 필수, 머지 브랜치 자동 삭제).
- Claude는 클라우드 세션에서 일해 사용자 컴퓨터의 `.env.local`을 볼 수 없다. 실제 Supabase·LLM 연결 확인은 사용자가 한다(미리보기 배포 후에는 링크로).
- 이 클라우드 환경에서는 `ui.shadcn.com`이 막혀 있어 shadcn 컴포넌트는 같은 형식으로 직접 작성한다.
- 머지 필수 검사는 `CI`(lint · typecheck · test · e2e)뿐이다. `DB` 검사는 DB 파일을 고친 PR에서만 돈다.
- 백로그 항목 하나 = 이슈 하나 = PR 하나. 큰 항목도 쪼개지 않는다.
- 보안이 중요한 PR(인증, RLS)은 올리기 전에 `security-review`를 돌린다.
- 반복 절차(작업 시작~PR, DB 변경)는 M0-3·M0-5를 거친 뒤 프로젝트 스킬(`.claude/skills/`)로 만들지 검토한다.
- 연결하면 좋은 커넥터: Supabase(SQL 복사·붙여넣기 대신 직접 적용), Vercel(배포 로그 확인). 사용자가 claude.ai 설정에서 연결한다.
