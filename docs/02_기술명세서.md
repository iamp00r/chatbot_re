# 02. 기술 명세서 — 가칭 **Loom**

> 문서 버전: v0.1 (2026-11-27)
> 전제: `01_기획서.md`의 기능 ID(F-xx-n)를 참조한다. 구현 순서와 인수 조건은 `03_MVP.md`에 있다.

---

## 1. 설계 원칙

1. **기억은 데이터다.** 기억을 프롬프트 텍스트 덩어리가 아니라 행(row)으로 저장한다. 그래야 보여 주고, 고치고, 거르고, 평가할 수 있다.
2. **사용자가 최종 권한을 갖는다.** 잠긴 항목은 자동 파이프라인이 절대 덮어쓰지 않는다.
3. **지우지 않고 무효화한다.** 자동으로 바뀐 사실은 `invalidated`/`superseded` 상태로 남긴다. 되감기와 이력 추적이 쉬워진다(Graphiti의 비손실 갱신 방식에서 착안).
4. **화자 관점으로 조립한다.** 프롬프트는 "지금 말할 캐릭터"를 기준으로 매번 따로 조립한다.
5. **핫 패스는 가볍게.** 응답 생성 경로에서는 LLM 호출을 한 번만 한다. 추출·요약은 응답이 끝난 뒤 비동기로 돌린다.
6. **모든 것을 관측할 수 있게.** 응답마다 실제 프롬프트, 주입된 기억 ID, 토큰, 지연을 기록한다.

## 2. 기술 스택

| 계층 | 선택 | 이유 |
|---|---|---|

| DB | **Supabase Postgres** | 인증, RLS, 스토리지, pgvector, pg_trgm 한곳에서 |
| ORM / 마이그레이션 | Drizzle ORM + SQL 마이그레이션 | 타입 안전, SQL에 가까움 |
| 인증 | Supabase Auth (Google OAuth, 이메일 매직링크) | |
| 파일 | Supabase Storage (아바타) | |
| 표 편집 | TanStack Table | 인라인 편집, 정렬, 필터 |
| 그래프 뷰 | **React Flow (@xyflow/react)** + 자동 배치(d3-force 또는 elkjs) | 노드 드래그, 커스텀 노드, 성능 |
| 검증 | Zod | LLM 구조화 출력과 API 입력 검증을 같은 스키마로 |

| 배포 | Vercel(Hobby) + Supabase(Free) | 개인·비상업 실험용 |

**착수 시 고정한 버전 (M0-1, 2026-11-27):** Next.js 16.4 · React 19.3 · Tailwind CSS 4.3 · shadcn/ui(new-york, neutral) · Vitest 5 · Playwright 1.65 · Node.js 22 · pnpm 10. 폰트는 외부 다운로드 없이 한글 시스템 폰트 스택을 쓴다.

**무료 티어 제약 (2026-11 기준, 착수 시 재확인)**
- Supabase Free: DB 500MB, 파일 1GB, 활성 프로젝트 2개, **7일 동안 요청이 없으면 일시정지**.
- Vercel Hobby: 개인·비상업 용도. 서버리스 함수 최대 실행 시간 제한이 있으므로 추출 작업은 짧게 쪼갠다.

### 2.1 LLM 구성 (설정으로 교체 가능)

| 용도 | 기본 후보 | 비고 |
|---|---|---|
| 채팅 응답 | Gemini Flash 계열 또는 DeepSeek V4 Flash | MVP ① 초기에 블라인드 비교로 결정 |
| 기억 추출·요약 | 가장 싼 모델 (Gemini Flash-Lite 계열 등) | 구조화 출력(JSON) 지원 필수 |
| 모더레이션 | 전용 분류 API (예: OpenAI moderation 엔드포인트) | 무료 여부와 한국어 성능은 착수 시 확인 |
| 임베딩 (v1) | 저가 임베딩 모델 + pgvector | MVP에서는 쓰지 않음 |

가격 메모(2026-11 조사): Gemini 3.1 Flash-Lite는 100만 토큰당 입력 $0.25 / 출력 $1.50. DeepSeek V4 Flash는 시간대별 차등 요금(피크가 비피크의 2배)이고 올해 여러 번 바뀌었다. 계산할 때는 공식 가격 페이지를 다시 확인한다.

```ts
// src/lib/llm/config.ts — 모델은 코드가 아니라 설정에서 고른다
export const MODELS = {
  chat:       env.LLM_CHAT_MODEL,      // 예: "google:gemini-x-flash"
  extract:    env.LLM_EXTRACT_MODEL,   // 예: "google:gemini-x-flash-lite"
  summarize:  env.LLM_SUMMARY_MODEL,
} as const;
```

## 3. 시스템 아키텍처

```
┌──────────── 브라우저 (Next.js 클라이언트) ─────────────┐
│ 채팅 UI · 기억 표(TanStack) · 그래프(React Flow)       │
└───────────┬──────────────────────────────┬─────────────┘
            │ HTTPS (스트리밍 응답)         │ Supabase JS (인증, RLS 읽기)
┌───────────▼──────────── Next.js 서버 (Vercel) ─────────────────────────┐
│ Route Handlers                                                        │
│  ├─ POST /api/rooms/:id/generate  ──► Turn Orchestrator               │
│  │        ① 모더레이션(입력)                                          │
│  │        ② 화자 선택 (Speaker Selector)                              │
│  │        ③ 기억 검색 (Memory Retriever, 화자 관점)                    │
│  │        ④ 프롬프트 조립 (Prompt Builder)                             │
│  │        ⑤ LLM 스트리밍 ──► 클라이언트                                │
│  │        ⑥ 완료 시 저장 + 출력 모더레이션                             │
│  │        ⑦ after(): 기억 작업 큐에 등록                               │
│  ├─ /api/memory/*   CRUD (표·그래프 편집)                              │
│  └─ /api/jobs/run   기억 작업 실행기 (추출·요약, 멱등)                  │
│                                                                       │
│ LLM Gateway (AI SDK)  ─► Google / DeepSeek / …                       │
└───────────┬───────────────────────────────────────────────────────────┘
            │ SQL (Drizzle, 서비스 역할)
┌───────────▼──────────── Supabase ───────────────────────────────────────┐
│ Postgres(+pg_trgm, pgvector) · Auth · Storage                          │
└─────────────────────────────────────────────────────────────────────────┘
```

별도 큐 인프라 없이 `memory_jobs` 테이블을 큐로 쓴다. 응답이 끝나면 `after()`(Next.js의 응답 후 실행)로 작업을 실행하고, 실패하거나 시간이 초과되면 다음 요청 때 또는 클라이언트의 재시도 호출로 다시 집어 간다.

## 4. 데이터 모델

### 4.1 ERD 개요

```
profiles 1─* characters
profiles 1─* stories 1─* story_characters *─1 characters
stories  1─* canon_nodes / canon_edges / canon_memories   (원작 기억 템플릿)
profiles 1─* personas
profiles 1─* rooms *─1 stories
rooms 1─* room_participants *─1 characters
rooms 1─* messages
rooms 1─* mem_nodes 1─* mem_edges
rooms 1─* memories *─* mem_nodes   (memory_subjects)
memories *─* mem_nodes             (memory_knowers: 아는 사람)
rooms 1─* memory_ops (변경 기록)
rooms 1─* memory_jobs
messages 1─1 generation_logs
```

### 4.2 스키마 (Postgres DDL 요약)

```sql
-- 확장
create extension if not exists pg_trgm;
create extension if not exists vector;     -- v1 임베딩용, 미리 활성화

-- 사용자
create table profiles (
  id uuid primary key references auth.users on delete cascade,
  nickname text not null,
  avatar_url text,
  created_at timestamptz default now()
);

-- 캐릭터
create table characters (
  id uuid primary key default gen_random_uuid(),
  owner_id uuid not null references profiles on delete cascade,
  name text not null,
  tagline text,                     -- 한 줄 소개 (표시용, 프롬프트 미사용)
  avatar_url text,
  appearance text,                  -- 외형
  personality text,                 -- 성격
  speech_style text,                -- 말투 ("~체" 이름 + 규칙 + 예시 대사 2~3개)
  background text,                  -- 배경
  rules text,                       -- 반드시 지킬 것
  example_dialogues text check (char_length(example_dialogues) <= 2000),
  pronoun text,                     -- 서술 시 지칭 (그/그녀/이름)
  visibility text not null default 'private'
    check (visibility in ('private','unlisted','public')),
  review_status text not null default 'none'
    check (review_status in ('none','pending','approved','rejected')),
  created_at timestamptz default now(),
  updated_at timestamptz default now()
);

-- 작품 (1:1도 작품)
create table stories (
  id uuid primary key default gen_random_uuid(),
  owner_id uuid not null references profiles on delete cascade,
  title text not null,
  description text,                 -- 소개글 (표시용)
  world_setting text,               -- 세계관·기본 상황·진행 방향 (프롬프트용)
  intro text not null,              -- 첫 메시지
  intro_speaker_id uuid references characters, -- null이면 내레이터
  tags text[] default '{}',
  visibility text not null default 'private',
  review_status text not null default 'none',
  created_at timestamptz default now(),
  updated_at timestamptz default now()
);

create table story_characters (
  story_id uuid references stories on delete cascade,
  character_id uuid references characters on delete cascade,
  position int not null default 0,
  talkativeness real not null default 0.5 check (talkativeness between 0 and 1),
  primary key (story_id, character_id)
);

-- 원작 기억 템플릿 (작품 제작자가 정의, 채팅방 시작 시 복사)
create table canon_nodes (
  id uuid primary key default gen_random_uuid(),
  story_id uuid not null references stories on delete cascade,
  kind text not null,               -- mem_nodes.kind와 같은 값
  name text not null,
  aliases text[] default '{}',
  summary text,
  character_id uuid references characters,   -- 등장 캐릭터 노드면 연결
  is_user boolean not null default false     -- 사용자(페르소나) 자리 노드
);
create table canon_edges (
  id uuid primary key default gen_random_uuid(),
  story_id uuid not null references stories on delete cascade,
  src uuid not null references canon_nodes on delete cascade,
  dst uuid not null references canon_nodes on delete cascade,
  relation text not null, description text, affinity int, directed boolean default true
);
create table canon_memories (
  id uuid primary key default gen_random_uuid(),
  story_id uuid not null references stories on delete cascade,
  content text not null, kind text not null default 'fact', importance int default 3,
  subject_node_ids uuid[] default '{}',
  knower_node_ids uuid[]            -- null = 모두 앎
);

-- 페르소나
create table personas (
  id uuid primary key default gen_random_uuid(),
  owner_id uuid not null references profiles on delete cascade,
  name text not null,
  description text,                 -- 외형·성격·특이사항
  is_default boolean default false
);

-- 채팅방
create table rooms (
  id uuid primary key default gen_random_uuid(),
  owner_id uuid not null references profiles on delete cascade,
  story_id uuid not null references stories,
  persona_id uuid references personas,
  title text,
  summary text default '',          -- 줄거리 요약 (F-ME-8)
  summary_locked boolean default false,
  summary_upto_seq bigint default 0,     -- 요약에 반영된 마지막 메시지 seq
  extracted_upto_seq bigint default 0,   -- 기억 추출에 반영된 마지막 메시지 seq
  next_seq bigint not null default 1,
  settings jsonb not null default '{}',  -- 모델, 응답 길이, 자동 이어 말하기 수 등
  created_at timestamptz default now(),
  updated_at timestamptz default now()
);

create table room_participants (
  room_id uuid references rooms on delete cascade,
  character_id uuid references characters,
  in_scene boolean not null default true,     -- F-MC-5 장면 참여
  talkativeness real not null default 0.5,
  node_id uuid,                                -- 이 캐릭터의 mem_nodes.id (FK는 생성 후 지정)
  primary key (room_id, character_id)
);

-- 메시지
create table messages (
  id uuid primary key default gen_random_uuid(),
  room_id uuid not null references rooms on delete cascade,
  seq bigint not null,                    -- 방 안의 순서 (같은 seq = 재생성 후보들)
  variant int not null default 0,         -- 재생성 후보 번호
  is_selected boolean not null default true,
  role text not null check (role in ('user','character','narrator','system')),
  character_id uuid references characters,   -- role=character일 때
  content text not null,
  whisper_to uuid[],                       -- F-MC-6: 귓속말 대상 character_id들
  is_ooc boolean not null default false,   -- F-CH-7
  present_character_ids uuid[] not null default '{}', -- 생성 시점에 장면에 있던 캐릭터
  deleted_at timestamptz,                  -- 되감기(소프트 삭제)
  edited_at timestamptz,
  flagged boolean not null default false,  -- 모더레이션
  created_at timestamptz default now()
);
create unique index messages_room_seq_variant on messages(room_id, seq, variant);
create index messages_room_active on messages(room_id, seq) where deleted_at is null and is_selected;

-- ───────────── 기억 그래프 ─────────────
create table mem_nodes (
  id uuid primary key default gen_random_uuid(),
  room_id uuid not null references rooms on delete cascade,
  kind text not null check (kind in ('character','user','npc','place','item','event','group','concept')),
  name text not null,
  aliases text[] not null default '{}',
  summary text default '',                 -- 한두 문장 요약
  attributes jsonb not null default '{}',  -- {"외형":"…","현재 상태":"부상"} 등 자유 속성
  character_id uuid references characters, -- 참여 캐릭터 노드
  origin text not null check (origin in ('canon','auto','user')),
  locked boolean not null default false,
  status text not null default 'active' check (status in ('active','invalidated','merged')),
  merged_into uuid references mem_nodes,
  source_seqs bigint[] not null default '{}',
  layout jsonb,                            -- 그래프 뷰 좌표 {x,y}
  created_at timestamptz default now(),
  updated_at timestamptz default now()
);
create index mem_nodes_room on mem_nodes(room_id) where status = 'active';
create index mem_nodes_name_trgm on mem_nodes using gin (name gin_trgm_ops);

create table mem_edges (
  id uuid primary key default gen_random_uuid(),
  room_id uuid not null references rooms on delete cascade,
  src uuid not null references mem_nodes on delete cascade,
  dst uuid not null references mem_nodes on delete cascade,
  relation text not null,          -- "소꿉친구", "라이벌", "짝사랑"
  description text default '',
  affinity int check (affinity between -100 and 100),  -- src가 dst에게 느끼는 감정
  directed boolean not null default true,
  origin text not null, locked boolean not null default false,
  status text not null default 'active'
    check (status in ('active','superseded','invalidated')),
  superseded_by uuid references mem_edges,
  valid_from_seq bigint, valid_to_seq bigint,  -- 이야기 속 유효 구간 (시간 이력)
  source_seqs bigint[] not null default '{}',
  created_at timestamptz default now(),
  updated_at timestamptz default now()
);

create table memories (
  id uuid primary key default gen_random_uuid(),
  room_id uuid not null references rooms on delete cascade,
  content text not null,           -- 한 문장. 3인칭, 이름 명시 ("도윤은 …")
  kind text not null default 'fact'
    check (kind in ('fact','event','promise','secret','preference','status')),
  importance int not null default 3 check (importance between 1 and 5),
  knowledge text not null default 'scoped'
    check (knowledge in ('everyone','scoped')),   -- everyone = 세계의 공지 사실
  story_time text,                  -- 이야기 속 시점 표현 ("축제 이틀 전")
  origin text not null, locked boolean not null default false,
  pinned boolean not null default false,          -- 항상 주입
  status text not null default 'active'
    check (status in ('active','superseded','invalidated')),
  superseded_by uuid references memories,
  source_seqs bigint[] not null default '{}',
  last_used_at timestamptz,         -- 검색 점수(최근 사용)용
  use_count int not null default 0,
  embedding vector(768),            -- v1
  created_at timestamptz default now(),
  updated_at timestamptz default now()
);
create index memories_room_active on memories(room_id) where status = 'active';
create index memories_content_trgm on memories using gin (content gin_trgm_ops);

create table memory_subjects (   -- 기억이 "누구/무엇에 관한" 것인가
  memory_id uuid references memories on delete cascade,
  node_id uuid references mem_nodes on delete cascade,
  primary key (memory_id, node_id)
);
create table memory_knowers (    -- 기억을 "누가 아는가" (knowledge='scoped'일 때)
  memory_id uuid references memories on delete cascade,
  node_id uuid references mem_nodes on delete cascade,   -- kind in (character, user, npc)
  primary key (memory_id, node_id)
);
create index memory_knowers_node on memory_knowers(node_id);

-- 변경 기록 (F-ME-6, 되돌리기·감사)
create table memory_ops (
  id bigserial primary key,
  room_id uuid not null references rooms on delete cascade,
  job_id uuid,
  actor text not null check (actor in ('auto','user','system')),
  op text not null,                -- add_node / update_node / add_edge / supersede_edge / add_memory / …
  target_table text not null, target_id uuid not null,
  before jsonb, after jsonb,
  status text not null default 'applied' check (status in ('applied','proposed','rejected','reverted')),
  created_at timestamptz default now()
);

-- 비동기 작업 큐
create table memory_jobs (
  id uuid primary key default gen_random_uuid(),
  room_id uuid not null references rooms on delete cascade,
  kind text not null check (kind in ('extract','summarize','invalidate_after')),
  from_seq bigint, to_seq bigint,
  status text not null default 'queued' check (status in ('queued','running','done','failed')),
  attempts int not null default 0,
  locked_until timestamptz,
  error text,
  created_at timestamptz default now()
);
create unique index memory_jobs_dedupe on memory_jobs(room_id, kind, to_seq)
  where status in ('queued','running');

-- 생성 로그 (프롬프트 검사기 F-AD-2, 평가, 비용)
create table generation_logs (
  id uuid primary key default gen_random_uuid(),
  room_id uuid references rooms on delete cascade,
  message_id uuid references messages on delete cascade,
  purpose text not null,            -- chat / extract / summarize / moderate
  model text not null,
  prompt jsonb not null,            -- 조립된 메시지 배열 전체
  injected_memory_ids uuid[] default '{}',
  injected_edge_ids uuid[] default '{}',
  input_tokens int, output_tokens int, cached_tokens int,
  ttft_ms int, total_ms int,
  finish_reason text, error text,
  created_at timestamptz default now()
);

-- 줄거리 스냅샷 (되감기 시 복원용, 방당 최근 10개 유지)
create table room_summaries (
  id bigserial primary key,
  room_id uuid not null references rooms on delete cascade,
  upto_seq bigint not null,
  text text not null,
  created_at timestamptz default now()
);

-- 신고 (v1): reports(id, reporter_id, target_type, target_id, reason, status, created_at)
```

### 4.3 RLS 정책 (요약)
- `profiles`, `personas`, `rooms` 이하 채팅방 소속 테이블: `owner_id = auth.uid()`(또는 채팅방 소유자)만 읽기·쓰기.
- `characters`, `stories`, `canon_*`: 소유자는 전부 가능. 그 외에는 `visibility in ('public','unlisted') and review_status='approved'`(공개)일 때 **읽기만**.
- 서버 Route Handler는 서비스 역할 키로 쓰기 작업을 하되, 매 요청마다 소유권을 코드에서 다시 확인한다(이중 방어).
- `generation_logs`: 본인 채팅방 것만 읽기(프롬프트 검사기).
- 자동 파이프라인 전용 테이블(`memory_ops`, `memory_jobs`, `generation_logs`, `room_summaries`)은 사용자에게 **읽기만** 허용한다. 쓰기는 서버(서비스 역할)만 한다.
- 채팅방을 만들 때는 본인 소유이면서 **읽을 수 있는 작품**(내 것 또는 공개·승인)이어야 한다.
- 정책은 로그인 사용자(`authenticated`)에게만 준다. 로그인하지 않으면(`anon`) 아무것도 볼 수 없다.
- 소유권 판정은 `private` 스키마의 `security definer` 함수(`owns_room`, `owns_story`, `can_read_story`, `owns_memory`)로 한다(정책 재귀와 성능 문제 방지).

### 4.4 정합성 규칙
- 메시지 "활성 경로" = `deleted_at is null and is_selected` 를 seq 순으로 정렬한 것.
- seq당 선택된 변형은 정확히 하나(트랜잭션으로 보장).
- 노드 이름은 방 안에서 대소문자와 공백을 무시하고 유일해야 한다(active 상태끼리). 별칭이 겹치면 병합 후보로 표시한다.
- `memory_knowers`의 노드는 인물 종류(`character`, `user`, `npc`)만 허용(트리거로 검사).
- `memory_subjects`·`memory_knowers`·`mem_edges`가 가리키는 노드는 같은 채팅방에 있어야 한다(트리거).
- seq당 선택된 변형 하나는 부분 유니크 인덱스 `(room_id, seq) where is_selected and deleted_at is null`로 DB가 보장한다. 스와이프는 "이전 변형 false → 새 변형 true" 순서로 바꾼다.
- `rooms.next_seq`는 되감기해도 줄이지 않는다. seq는 재사용하지 않으므로 되감기 후 새 메시지는 더 큰 seq를 받는다(소프트 삭제된 행과 겹치지 않음).
- 삭제 동작: 작품이 지워지면 그 작품의 채팅방도 지운다(cascade). 캐릭터를 가리키는 표시용 참조(`messages`, `mem_nodes`, `canon_nodes`, `stories.intro_speaker_id`)는 `set null`. 계정 삭제 시에는 작품을 먼저 지우는 트리거로 cascade 순서를 고정한다(남이 내 공개 작품으로 만든 방이 있어도 계정 삭제가 가능해야 함).

**구현 위치:** `supabase/migrations/*.sql`(DB의 기준). `src/lib/db/schema.ts`(Drizzle)는 쿼리 타입용으로 컬럼·키만 옮기고, `tests/db/schema-sync.test.ts`가 실제 DB와 컬럼이 같은지 확인한다. 마이그레이션은 Drizzle Kit이 아니라 SQL 파일로 관리한다. 검증은 `scripts/db-test-local.sh`(빈 Postgres + Supabase 흉내 스텁)로 하고, CI(`.github/workflows/db.yml`)에서도 돈다. `supabase/tests/rls.test.sql`은 Supabase SQL Editor에서도 그대로 실행할 수 있다(트랜잭션 후 rollback).

## 5. 채팅 턴 처리

### 5.1 사용자 메시지 1회의 흐름

```
POST /api/rooms/:id/generate
  body: { userMessage?: {content, whisperTo?, isOoc?}, mode: 'reply'|'continue'|'regenerate', targetSeq?, speakerId? }

1. 인증 + 방 소유 확인
2. (userMessage가 있으면) 입력 모더레이션 → 통과 시 messages에 저장 (seq = next_seq++)
3. 화자 선택 (§7.1). mode=continue면 사용자 입력 없이 다음 화자
4. 기억 검색 (§6.3, 화자 관점)
5. 프롬프트 조립 (§8)
6. LLM 스트리밍 시작 → 클라이언트로 토큰 전달
     · 스트림 첫 이벤트로 {speakerId, seq, variant} 메타데이터 전송
7. 완료(onFinish):
     · 출력 모더레이션 (걸리면 content를 차단 안내로 바꾸고 flagged=true)
     · messages 저장, generation_logs 저장
     · memories.last_used_at / use_count 갱신 (주입된 기억)
8. after(): 조건이 맞으면 memory_jobs 등록 후 실행
     · extract: (마지막 추출 이후 활성 메시지 수) ≥ EXTRACT_EVERY (기본 6 = 사용자·캐릭터 3번씩 주고받은 분량)
     · summarize: 요약에 반영되지 않은 메시지 수 ≥ SUMMARY_EVERY (기본 20)
```

- **재생성(regenerate)과 스와이프는 마지막 AI 메시지에서만** 할 수 있다(대부분의 서비스와 같은 방식. 더 앞의 메시지를 다시 만들려면 되감기 후 재생성). 같은 seq에 `variant+1`로 새 메시지를 만들고 선택을 옮긴다. 그 seq가 이미 추출에 반영됐다면 `invalidate_after(seq − 1)`의 기억 부분(§6.5의 2~6단계)을 적용하고, 다음 추출 때 다시 뽑는다.
- **중간 메시지 수정:** 메시지 순서는 유지된다. 그 seq를 근거로 한 자동 기억 중 근거가 그 seq 하나뿐인 것은 무효화하고, 근거가 여럿인 것은 "확인 필요" 표시를 단다. 그 뒤 `extract` 작업을 `from_seq = to_seq = 수정한 seq`로 등록해 해당 메시지만 다시 추출한다.
- **스트림 중단:** 사용자가 중단하면 그때까지의 텍스트를 저장하고 `finish_reason='aborted'`로 기록한다.

### 5.2 스트리밍
- AI SDK의 `streamText` + UI 메시지 스트림 응답을 쓴다. 클라이언트는 `useChat` 대신, 다중 화자와 스와이프를 지원하는 **자체 훅**(`useRoomStream`)을 만든다. 메시지 모델이 seq/variant 구조라서다.
- 다중 캐릭터 이어 말하기는 **한 번의 HTTP 요청에 화자 하나**다. 클라이언트가 응답을 다 받은 뒤 `mode=continue`로 다음 요청을 보낸다(최대 N회, 사용자가 언제든 중단 가능). 서버리스 실행 시간이 짧게 유지되고 실패를 처리하기 쉽다.

## 6. 기억 시스템

### 6.1 세 가지 층

| 층 | 저장 위치 | 용도 | 주입 방식 |
|---|---|---|---|
| **작업 기억** | 최근 메시지 | 직전 맥락 | 원문 그대로, 토큰 예산 안에서 최근부터 |
| **줄거리** | `rooms.summary` | 전체 흐름 | 항상 주입(약 400~800자) |
| **구조화 기억** | 노드·관계·기억 | 사실, 관계, 비밀, 약속 | 화자 관점 검색 → 예산 안에서 선별 |

줄거리만 쓰면 세부 사항이 뭉개지고, 구조화 기억만 쓰면 흐름이 끊긴다. 두 방식을 함께 쓰고, 평가(§11)에서 각각의 기여를 따로 잰다.

### 6.2 추출 파이프라인 (extract job)

Mem0의 "후보 추출 → 기존 기억과 대조해 ADD/UPDATE/DELETE/NOOP 결정" 2단계 방식을 참고하되, **한 번의 호출**에 대조까지 맡기고 DELETE 대신 **무효화(invalidate)/대체(supersede)**를 쓴다. 참고로 Mem0도 2026년 v3에서 UPDATE/DELETE를 판단하는 별도 단계를 없애고 한 번에 추가만 하는 방식으로 바꿨다. 호출 수를 줄이려는 방향은 같다.

**입력**
1. 대상 메시지: `extracted_upto_seq` 이후의 활성 메시지(최대 12개). 각 메시지에 `seq`, 화자, `present_character_ids`, `whisper_to`를 붙인다.
2. 기존 노드 목록: 방 안 활성 노드 전체(id, kind, name, aliases, locked). 노드가 많으면 대상 메시지에 언급된 것 + 참여 캐릭터 + 사용자로 줄인다.
3. 관련 기존 기억: 대상 메시지에 언급된 노드에 연결된 활성 기억 상위 30개(id, content, locked).
4. 관련 관계: 언급된 노드에 연결된 활성 엣지.

**출력 (Zod 스키마, 구조화 출력)**

```ts
const Op = z.discriminatedUnion('op', [
  z.object({ op: z.literal('add_node'), tempId: z.string(), kind: NodeKind,
             name: z.string(), aliases: z.array(z.string()).default([]),
             summary: z.string().max(200), sourceSeqs: z.array(z.number()) }),
  z.object({ op: z.literal('update_node'), id: z.string(),
             summary: z.string().max(200).optional(),
             attributes: z.record(z.string()).optional(),
             addAliases: z.array(z.string()).optional(), sourceSeqs: z.array(z.number()) }),
  z.object({ op: z.literal('upsert_edge'), src: NodeRef, dst: NodeRef,
             relation: z.string().max(30), description: z.string().max(150),
             affinity: z.number().int().min(-100).max(100).nullable(),
             replacesEdgeId: z.string().nullable(),     // 관계가 바뀌었으면 이전 엣지
             sourceSeqs: z.array(z.number()) }),
  z.object({ op: z.literal('add_memory'), content: z.string().max(200),
             kind: MemoryKind, importance: z.number().int().min(1).max(5),
             subjects: z.array(NodeRef).min(1),
             knowers: z.union([z.literal('everyone'), z.array(NodeRef)]),
             replacesMemoryId: z.string().nullable(),   // 갱신이면 이전 기억
             storyTime: z.string().nullable(), sourceSeqs: z.array(z.number()) }),
  z.object({ op: z.literal('invalidate'), table: z.enum(['memories','mem_edges']),
             id: z.string(), reason: z.string() }),
]);
const ExtractResult = z.object({ ops: z.array(Op).max(25) });
// NodeRef = 기존 노드 id 또는 같은 응답의 add_node tempId
```

**추출 프롬프트의 핵심 규칙** (전문은 `src/lib/memory/prompts/extract.ts`)
- 이야기를 이어 가는 데 **나중에 다시 필요한 정보**만 뽑는다. 인사, 감탄, 일회성 동작은 버린다.
- 기억은 한 문장, 3인칭, 이름 명시로 쓴다. "그녀는" 같은 대명사는 금지.
- 중요도 기준: 5 = 정체성·관계를 바꾸는 사건, 비밀, 약속 / 4 = 중요한 사건·선호 / 3 = 쓸모 있는 세부 사항 / 1~2 = 사소함(되도록 만들지 않음).
- **아는 사람 판정:**
  - 기본값 = 그 메시지가 생성될 때 장면에 있던 캐릭터(`present_character_ids`) + 사용자.
  - `whisper_to`가 있는 메시지에서 나온 기억 = 귓속말 대상 + 사용자만.
  - 캐릭터의 속마음(괄호 표기) = 그 캐릭터 본인만.
  - 캐릭터가 대사로 **다른 사람에게 말한** 내용이면, 그 자리에 있던 사람들이 알게 된다.
  - 세계의 공지 사실(날씨, 공개 행사 등)은 `everyone`.
- 이미 있는 기억과 같은 내용이면 만들지 않는다(NOOP). 더 자세하거나 바뀐 내용이면 `replacesMemoryId`를 단다.
- 관계가 바뀌면(적 → 동료) 새 엣지에 `replacesEdgeId`를 단다.
- `locked: true`인 항목은 수정하거나 대체할 수 없다. 모순되면 `add_memory`로 새 사실만 남긴다(적용 단계에서 "제안"으로 바뀜).

**적용 단계 (트랜잭션, 코드에서 검증)**
1. 스키마 검증에 실패하면 1회 재시도하고, 또 실패하면 job을 `failed`로 둔다.
2. 존재하지 않는 id를 참조하는 연산은 버린다(환각 방지).
3. `tempId`를 실제 id로 바꾼다. `add_node`는 이름·별칭이 trigram 유사도 0.8 이상인 기존 노드가 있으면 새로 만들지 않고 그 노드에 연결한다.
4. 잠긴 항목을 대상으로 한 `update/replace/invalidate` → 적용하지 않고 `memory_ops.status='proposed'`로 기록한다(UI에 "AI 제안" 배지).
5. `replaces*` → 이전 행을 `status='superseded'`, `superseded_by=새 id`로. 엣지는 `valid_to_seq`를 채운다.
6. 모든 변경을 `memory_ops`에 before/after로 남긴다.
7. `rooms.extracted_upto_seq` 갱신.

### 6.3 검색 (화자 관점, 핫 패스, LLM 호출 없음)

화자 C, 사용자 노드 U, 최근 메시지 K개(기본 8)가 주어졌을 때:

```
① 필수 기억 (항상)
   - C에 연결된 활성 엣지 전부 (C→X, X→C), U↔다른 참여자 엣지
   - pinned = true 이고 C가 아는 기억
② 후보 기억 = 활성 기억 중 "C가 아는 것"
   knows(C, m) := m.knowledge = 'everyone'
                  OR exists(memory_knowers where memory_id=m.id and node_id=C.node)
③ 점수
   score(m) = 0.40·(importance/5)
            + 0.35·mention(m)     // 최근 K개 메시지 + 사용자 입력에 m의 주제 노드 이름·별칭이 나오면 1
            + 0.15·recency(m)     // exp(-(현재 seq - max(source_seqs)) / 200)
            + 0.10·textSim(m)     // 사용자 입력과 content의 trigram 유사도
④ 점수순으로 담되, 예산(MEMORY_TOKEN_BUDGET, 기본 1,200토큰)을 넘으면 중단
⑤ 언급된 노드의 summary/attributes도 예산 안에서 추가 (예: 외형, 현재 상태)
```

- 가중치는 설정값으로 두고 평가 하네스로 조정한다.
- v1: `textSim`을 임베딩 코사인 유사도로 바꾼다(pgvector). 기억이 몇백 개 이하인 MVP 규모에서는 trigram + 언급 매칭으로 충분하다고 본다. 평가로 검증한다.
- 검색 결과(주입된 기억·엣지 id)는 `generation_logs`에 저장 → "이번 응답에 쓰인 기억 보기"(F-ME-9).

### 6.4 주입 형식

사실관계는 YAML 형식이 짧고 소속 관계가 분명하다는 제작자 경험담을 반영해, 기억 블록은 YAML 비슷한 형식으로 넣는다.

```yaml
# 리아가 알고 있는 것 (리아의 관점)
relationships:
  - 리아 → 하준(사용자): 소꿉친구, 호감 +60 · 어릴 적 약속을 기억함
  - 리아 → 도윤: 경계함, 호감 -20 · 도윤이 뭔가 숨긴다고 의심
facts:
  - [약속·5] 하준과 리아는 축제 마지막 날 시계탑에서 만나기로 했다 (축제 이틀 전)
  - [사건·4] 리아는 어제 도서관에서 찢어진 지도 조각을 주웠다
entities:
  - 시계탑: 마을 중앙. 밤 10시 이후 출입 금지
```

### 6.5 되감기·재생성과 기억 무효화 (F-CH-4)

```
invalidate_after(room, seq S):
  1. messages: seq > S → deleted_at = now()      (재생성의 경우 해당 seq의 이전 변형만)
  2. origin='auto' AND locked=false 이고 min(source_seqs) > S 인 기억·엣지·노드
       → status = 'invalidated' (memory_ops에 기록)
  3. source_seqs 일부만 S 이후인 항목 → source_seqs에서 S 이후 값을 빼고 유지
  4. 잠긴 항목 또는 사용자가 만든 항목 → 유지하되, 근거가 사라졌다고 알림 표시
  5. rooms.extracted_upto_seq = min(현재값, S), summary_upto_seq도 같게
     (요약이 S 이후 내용을 포함했다면 summarize job을 다시 등록: 이전 요약 스냅샷이 있으면 복원)
  6. 대체(superseded)됐던 이전 항목 중, 대체한 항목이 무효화된 것 → 다시 active
     (엣지는 valid_to_seq = null로 되돌림)
  7. 이 모든 단계를 하나의 트랜잭션으로 실행하고, 진행 중인 같은 방의 extract/summarize 작업은 취소
```

요약 복원을 위해 `room_summaries(room_id, upto_seq, text)` 스냅샷을 요약할 때마다 저장한다(최근 10개 유지).

### 6.6 줄거리 요약 (summarize job)
- 입력: 이전 요약 + 요약에 아직 반영되지 않은 메시지(최대 30개).
- 출력: 갱신된 요약(최대 800자). 시간순 단락, 등장인물 이름 명시.
- `summary_locked = true`면 덮어쓰지 않고 "제안"으로만 보관한다.

### 6.7 사용자 편집 API의 의미
- 사용자가 만들거나 수정한 행: `origin='user'`(새로 만든 경우), `locked=true`(수정한 경우 자동).
- 사용자가 지운 행: `status='invalidated'`(실제 삭제는 하지 않고, "휴지통"에서 복구 가능).
- 아는 사람 편집: `memory_knowers` 행 추가/삭제 또는 `knowledge` 토글.
- 노드 병합: A를 B로 합치면 A의 엣지·기억 연결을 B로 옮기고 A는 `status='merged'`.

## 7. 다중 캐릭터 대화

### 7.1 화자 선택 (Speaker Selector, 규칙 기반)

SillyTavern 그룹챗의 "자연 순서" 전략(언급된 캐릭터 우선, 수다 정도에 따라 끼어들기)을 참고한다.

```
selectSpeaker(room, lastMessages, userInput, explicitSpeakerId):
  candidates = room_participants where in_scene = true
  if explicitSpeakerId → 그 캐릭터
  if userInput.whisperTo → 귓속말 대상 중 첫 번째
  mentioned = candidates 중 이름·별칭이 userInput(continue 모드면 마지막 메시지)에 나온 캐릭터
             (방금 말한 캐릭터는 제외)
  if mentioned 있음 → 언급 순서대로 첫 번째
  else → 방금 말한 캐릭터를 뺀 후보에서 talkativeness 가중 랜덤
         (후보가 1명뿐이면 그 캐릭터)
```

- **귓속말에 대한 답장:** 귓속말 메시지에 대상 캐릭터가 바로 답하면, 답장 메시지도 같은 `whisper_to`를 이어받는다(대상 + 사용자만 앎). 다음 일반 메시지부터는 범위가 풀린다.
- **사용자 페르소나:** MVP에서는 사용자가 항상 장면에 있는 것으로 본다. 사용자 노드는 장면에서 생긴 모든 기억의 아는 사람에 들어간다.
- **이어 말하기(continue):** 클라이언트가 `auto_continue`(기본 0, 최대 3)만큼 `mode=continue` 요청을 연달아 보낸다. 서버는 마지막 메시지를 "입력"으로 보고 같은 선택 규칙을 적용한다. 같은 캐릭터가 연속으로 말하지 않는다.
- v2 감독 모드: 싼 모델에 "다음 화자 이름 또는 USER"만 묻는 호출을 추가한다.

### 7.2 화자별 프롬프트 (Swap 방식)
- 프롬프트에는 **현재 화자**의 상세 설정 전체와 **다른 참여자의 짧은 소개**(이름, 외형 한 줄, 말투 한 줄)만 넣는다. 말투가 섞이는 문제를 줄인다.
- 대화 기록의 각 메시지에는 화자 이름을 붙인다: `[도윤] *문을 연다* 늦었네.`
- 끝에 넛지를 단다: `지금은 {화자}의 차례다. {화자}의 대사와 행동만 쓴다. 다른 인물과 {사용자}의 대사는 쓰지 않는다.`
- **대화 기록도 화자 관점으로 거른다:** 화자 C가 없을 때 오간 메시지(`present_character_ids`에 C가 없음)와 C가 대상이 아닌 귓속말은 기록에서 빼고, 그 자리에 `(— 리아가 자리에 없는 동안 대화가 오갔다 —)` 한 줄만 넣는다. 이렇게 하지 않으면 known_by 필터를 해도 원문 기록으로 정보가 샌다.

## 8. 프롬프트 조립 (Prompt Builder)

프롬프트 캐싱(공급사 쪽 접두어 캐시)이 잘 맞도록 **변하지 않는 내용을 앞에, 변하는 내용을 뒤에** 둔다.

```
[system] ── 고정 (작품·화자별로 같음 → 캐시 대상)
  1. 플랫폼 규칙: 전연령 수위, 금지 사항, 출력 형식(*행동* + 대사),
     "사용자({{user}})의 대사·행동·생각을 대신 쓰지 않는다", OOC(< >) 처리 규칙
  2. 세계관 (stories.world_setting)
  3. 화자 캐릭터 상세 (외형/성격/말투/배경/반드시 지킬 것)
  4. 다른 참여자 소개 (다인캐일 때)
  5. 사용자 페르소나
  6. 예시 대화 (있으면, "형식 참고용이며 실제 사건이 아님" 표시)
[system] ── 변동
  7. 줄거리 요약
  8. 기억 블록 (§6.4, 화자 관점)
  9. 장면 정보: 지금 장면에 있는 인물, 응답 길이 지시
[messages] ── 최근 대화 (화자 관점으로 거른 것, 예산 안에서 최근부터)
[system or user 끝] ── 넛지: 이번 화자 + 핵심 규칙 한 번 더 (말투, 대사 도용 금지)
```

**토큰 예산 (기본값, 설정 가능)**

| 구역 | 예산 |
|---|---|
| 고정 영역(1~6) | ~2,500 (넘으면 제작 화면에서 경고) |
| 줄거리 | ~600 |
| 기억 블록 | ~1,200 |
| 최근 대화 | ~3,000 (최소 4개 메시지는 보장) |
| 출력 | max_tokens 600 |

토큰 수는 조립 단계에서 근사치(한국어는 글자 수 기반 추정치에 계수를 곱함)로 계산하고, 실제 사용량은 응답의 usage 값으로 기록해 계수를 보정한다.

**제작 경험담에서 가져온 규칙**
- 핵심 설정(외형·성격·말투)은 상세 본문에 있어야 한다. 예시 대화에만 있으면 잘 지켜지지 않는다 → 제작 화면에서 말투 칸을 필수로.
- 인트로 장면과 같은 장면을 예시 대화에 넣으면 같은 답이 반복된다 → 제작 화면에서 경고.
- 대사 도용 금지 규칙은 **맨 앞과 맨 끝**에 두 번 넣는다.

## 10. 안전·모더레이션

| 단계 | 방법 | 실패 시 |
|---|---|---|
| 입력 | 모더레이션 API (성적·폭력·자해·혐오 범주) | 저장하지 않고 안내 메시지. 자해 범주면 도움 안내 |
| 시스템 프롬프트 | 전연령 규칙 + 거절 방식("캐릭터를 유지한 채 자연스럽게 화제 전환") | — |
| 출력 | 응답 완료 후 모더레이션 (스트리밍 지연을 피하려고 사후 검사) | 메시지를 가리고 `flagged=true`, "다시 생성" 버튼 |
| 제작물 | 공개 요청 시 캐릭터·작품 텍스트 전체 검사 + 미성년 설정 × 연애 키워드 규칙 검사 | `review_status='rejected'` + 사유 |
| 기억 | 추출된 기억도 출력 모더레이션과 같은 기준으로 검사(가벼운 키워드 검사) | 저장하지 않음 |

- 사후 검사 방식이라 차단 전에 일부 문장이 화면에 잠깐 보일 수 있다. 실험 단계에서는 이를 감수하고, v1에서 문장 단위 버퍼링 검사를 검토한다.
- 투명성: 채팅 화면 상단과 각 AI 메시지에 "AI 생성" 표시(AI 기본법 투명성 의무 취지. 비공개 실험이지만 포트폴리오 품질 차원에서 적용).

## 11. 평가 하네스 (포트폴리오 핵심)

```
/eval
  scenarios/*.yaml     # 시나리오: 작품 설정 + 사용자 대사 스크립트 + 질문·정답
  run.ts               # 시나리오 재생 → 조건별 응답 수집
  judge.ts             # LLM 채점 (정답 포함 여부 0/1) + 사람 검수 표본
  report.ts            # 조건별 정확도, 유출률, 비용 표 → eval/reports/*.md
```

**시나리오 예 (비밀·약속·관계 변화)**
```yaml
id: secret-triangle-01
story: fixtures/stories/academy.yaml   # 리아, 도윤
turns: 60                               # 사용자 대사 스크립트 60줄 (whisper 포함)
probes:
  - after_turn: 60
    ask_as: 리아
    question: "축제 마지막 날 어디서 만나기로 했지?"
    expect_contains: ["시계탑"]
  - after_turn: 60
    ask_as: 리아
    question: "도윤이 나한테 숨기는 거 있어?"
    must_not_contain: ["왕족"]           # 도윤의 비밀은 리아가 모름 → 유출 검사
```

**비교 조건:** A) 최근 대화만 / B) A + 줄거리 / C) B + 구조화 기억(known_by 포함) / D) C에서 known_by 끔(유출 비교용).
**지표:** 회상 정확도, 유출률, 추출 정밀도(사람 검수 표본 50개), 턴당 토큰.

## 12. 관측성·비용

- `generation_logs`가 모든 LLM 호출을 기록한다(채팅·추출·요약·모더레이션).
- 일일 한도: `DAILY_TOKEN_LIMIT`(본인 실험용 안전장치). 넘으면 생성 API가 429를 반환한다.
- 비용 추정 = Σ(입력×단가 + 출력×단가 − 캐시 할인). 단가는 `model_prices` 설정 파일로 관리한다.
- 대략적 계산: 턴당 입력 ~7k + 출력 ~0.4k 토큰, 6메시지마다 추출 호출 1회(~4k/0.8k). 저가 Flash급 모델이면 1,000턴에 수 달러 수준으로 예상한다. 실제 값은 로그로 확인한다.

## 13. 보안·개인정보

- 비밀 키(LLM, 서비스 역할)는 서버 환경 변수로만 쓰고 클라이언트에 노출하지 않는다.
- RLS + 서버 소유권 검사 이중 방어.
- 입력 길이 제한: 사용자 메시지 2,000자, 캐릭터 각 칸 정해진 한도.
- 계정 삭제 시 cascade로 전부 삭제한다(F-AU-3).
- 프롬프트 인젝션: 캐릭터 설정과 사용자 입력은 "데이터"로 감싸 넣는다. 추출 결과는 스키마 검증과 id 화이트리스트로 방어한다.
- API 요청 속도 제한: 사용자당 분당 생성 20회.

| ADR-2 | 추출 1회 호출 + 코드 검증 적용 | Mem0식 2회 호출 | 비용·지연 절반. 검증 단계가 대조를 보완 |
| ADR-3 | 삭제 대신 무효화/대체 | 하드 삭제 | 되감기 복구, 이력, 되돌리기 |
| ADR-4 | MVP 검색은 규칙 점수(LLM·임베딩 없음) | 벡터 RAG | 핫 패스 지연 0, 소규모에서 충분. 평가로 검증 후 v1에서 임베딩 추가 |
| ADR-5 | 다인캐는 요청 하나에 화자 하나 | 한 번의 호출로 여러 화자 | 화자별 기억 필터가 가능하고, 말투 섞임이 줄고, 서버리스 시간 제한에 안전 |
| ADR-6 | 출력 모더레이션은 사후 검사 | 스트림 중간 검사 | 첫 토큰 지연 유지. 실험 단계에서 위험 감수 |
| ADR-7 | 1:1도 작품(등장인물 1명)으로 통일 | 캐릭터 채팅과 작품 채팅 분리 | 모델·코드 하나로 단순화 |
